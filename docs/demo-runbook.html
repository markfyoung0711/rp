Demo runbook: the leasing-outreach bot

What you type, what you show and what you say, in order. The bot is a command-line tool: records in, one decision per record out. Template mode is free, offline and deterministic.

Deadline 12:00 noon CT, Sep 24 Hold-out: 12 unseen records v0.2 · samples match every field $0 API cost by default

Before the interview

During the demo

  1. Show it works on the two samples

    uv run bot.py -i plans/sample.jsonl --compare

    On screen: each decision with its reasons, ✅ per field, then RUN STATS: decisions, latency vs the 2,000 ms p95 target, safety, PII redacted, API cost $0, and “Controllable fields … all match: 2/2”.

    Say

    “Every field matches both samples. Channel, send time, CTA, opt-out and next action are code; only the wording could come from a model, and by default it’s a template, so it’s free and deterministic.”

  2. Explain one decision

    uv run bot.py -i plans/sample.jsonl --only day0
    Say

    “SMS is Taylor’s first preferred channel with consent. Last contact Dec 8 at 09:04 plus day 0 at the 09:00 SMS hour has passed, so it rolls to Dec 9 at 09:00. New lead, 32 days to move-in, under 45, so the short-horizon welcome sequence.”

  3. Show two or three anticipated cases

    uv run bot.py -i tests/edge_cases.jsonl --only kids
    uv run bot.py -i tests/garbage_inputs.txt
    uv run bot.py -i tests/pii_cases.jsonl

    Point at: fair housing (same message) · messy paste (13 of 14 recovered) · PII redacted 81, leaked 0. The full list is below.

  4. Run their 12 hold-out records

    They send a file

    Save it as holdout.jsonl, then:

    uv run bot.py -i holdout.jsonl -o out/holdout.jsonl

    Add --compare if their records include expected: that’s your live score.

    They paste text

    Paste, then Ctrl+D. JSONL, a JSON list, pretty-printed or chat-style text all work.

    uv run bot.py --paste -o out/holdout.jsonl

    If something looks odd: nothing crashes. The bot outputs a no-send with a reason, and the warnings say what was repaired or assumed.

  5. Hand over the 12 outputs

    Send out/holdout.jsonl, or copy the block between === BEGIN OUTPUT === and === END OUTPUT ===. One line per record: task_id, next_message (or null), next_action, why, meta.

  6. Talk track: assumptions, then the roadmap

    State the assumptions below, then open plans/solution.md for what’s designed but not built: owner, support and renter views, database, login, sentiment, review sites, real SMS/email sending, reply handling.

AI wording and cost

Assumptions to say out loud

  1. Send time = last contact + the day number in the task ID, at 09:00 for SMS or 10:00 for email, moved to the next day if already past. Inferred from two samples; configurable.
  2. Channel = the first preferred channel with consent. Voice is modeled, not built.
  3. Next action: a new lead starts a sequence (short if ≤ 45 days to move-in, else long); anyone else gets a follow-up in 3 days.
  4. Property details come from one config file, never invented.
  5. No-send shape (next_message: null plus a reason) is my choice; the spec doesn’t define one.
  6. Personal data: only the first name, in the greeting. task_id is the only join key; identity belongs to the system of record.

Likely gotchas and quick answers

They askYou answer
“Is this an AI agent?”“An autonomous decision pipeline. Compliance-critical decisions are deterministic code; a model may write only the wording.”
“Is it really learning?”“The rules were inferred from the data and made configurable; in --llm mode the samples are few-shot examples for the wording.”
“A record type you’ve never seen?”Levels 1–3: new values hit default rows; odd formats are repaired and noted; unknown shapes are searched for fields, with confidence low. No consent → never send.
“What about PII?”“Only the first name leaves the bot. Twenty rental-PII categories are tested: 81 withheld, 0 leaked. Balances and account numbers never go in a message.”
“What if Anthropic is down?”“Template mode never calls it. With --llm, each record falls back to the template; decisions are identical.”
“100,000 records?”“52 s in template mode at $0. With --llm, about $170 on Haiku, or $85 via the Batch API; the bot shows that and stops first.”
“Change a rule live?”“Rules live in config/rules.yaml: one row, re-run.”
